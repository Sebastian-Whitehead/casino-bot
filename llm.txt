# Casino Bot Repository Map

Purpose: persistent context for future coding work in this repository. This is a map of the code as currently found, not a claim that every path is healthy.

## Project identity

- Python Discord gambling bot for a private/friends casino.
- Runtime framework used by the source: `nextcord`, imported as `nextcord` or `discord`.
- README says discord.py, and `requirements.txt` pins `discord.py==1.7.1`; verify the installed environment before changing dependency setup.
- Games: blackjack, slots, coin flip, and dice guessing.
- Persistence: SQLite database at `discord/economy.db` (ignored by git).
- Configuration: root `config.yml` (ignored by git); template is `config.yml.example`.
- Images/assets: `pictures/` and `discord/modules/cards/`; additional slot/coinflip/table assets are expected under `discord/modules/`.

## Planned economy service

The current economy is embedded in the bot as `discord/economy.db` and accessed directly through the singleton `Economy` class. The intended future direction is to separate it into a standalone service so the Discord bot, web dashboard, and administrative tools can share one source of truth.

Recommended shape:

```text
Discord bot  -+
Web dashboard  +-> Economy API -> PostgreSQL
Admin tools  -+
```

- Run the API and PostgreSQL with Docker Compose; the bot should call the API over the private Compose network.
- Keep Discord interaction code in the bot and move balances, transfers, and game settlement into the economy service.
- Prefer PostgreSQL over exposing SQLite across processes. SQLite remains suitable for the current single-process bot and migration source.
- Preserve the current money/credits contract during migration, then add an immutable transaction ledger and database transactions for concurrency safety.
- Settlement endpoints should accept idempotency/game IDs so retries cannot duplicate payouts.
- Authenticate each client with API keys, service tokens, or equivalent credentials; keep secrets in environment variables or Docker secrets.
- Migration path: implement the API around current behavior, import `economy.db`, switch the bot to an API client, test deductions/payouts/fees/refunds, then remove direct SQLite access.
- Treat this as financial state: authorization, locking, retries, audit history, backups, and persistent PostgreSQL storage are core requirements.
- The implementation-ready specification is in `economy_service_plan.md`; use it as the primary handoff document when creating the separate service project.

## Runtime entry point and import behavior

1. Run `python discord/bot.py` from the repository root.
2. `discord/bot.py` creates a Nextcord `commands.Bot` with member and message-content intents, disables the default help command, and imports shared values from `modules.helpers`.
3. `modules.helpers` executes `os.chdir(Path(__file__).parent.parent)`, changing the process working directory to `discord/`, then loads `../config.yml`.
4. The bot loads every `.py` file in `discord/cogs/` except `legacy_gambling.py` using `client.load_extension(...)`.
5. `client.run(TOKEN)` starts the bot.
6. `on_ready` starts the background thread cleanup task when enabled.

Important: because `helpers.py` changes the process cwd during import, relative paths elsewhere resolve from `discord/`, not necessarily from the original shell cwd. Prefer paths based on `__file__` when fixing path-sensitive code.

## Configuration contract

`config.yml` has a `bot` mapping containing:

- `token`: Discord credential; never copy this value into documentation or logs.
- `owner_ids`, `prefix`, `test_guild_id`.
- `casino_channel_id` and `restrict_to_casino_channel`: slash games reject interactions outside the configured channel when enabled.
- `casino_user_id`: legacy/fallback database ID used before login; after `on_ready`, the casino bank is bound to `client.user.id`.
- Monetary defaults: `default_bet`, `bonus_multiplier`, `bonus_cooldown`, `token_price`.
- Challenge policy: `challenge_fee_enabled` toggles the casino fee and `challenge_fee_percent` sets its percentage of the combined two-player pot.
- Payouts: `dice_multiplier`, `coinflip_multiplier`, `blackjack_multiplier`, `blackjack_blackjack_multiplier`, `slots_multipliers`.
- `track_casino_balance`: controls the owner-facing casino balance commands, but economy transfers themselves are implemented in `Economy.add_money`.

Top-level cleanup values:

- `thread_timeout_minutes` controls stale-thread age.
- `thread_cleanup_check_seconds` controls polling interval.

`helpers.py` exposes these as constants such as `DEFAULT_BET`, `SLOTS_DEFAULT_BET`, `COINFLIP_MULT`, `BLACKJACK_MULT`, `BLACKJACK_BJ_MULT`, `SLOTS_MULTS`, `CASINO_USER_ID`, and channel/cleanup settings.

## Core modules

### `discord/modules/economy.py`

- `Economy` is a process-level singleton.
- Opens/creates `discord/economy.db` and table `economy(user_id INTEGER PRIMARY KEY, money INTEGER, credits INTEGER)`.
- Entry tuple shape is `(user_id, money, credits)`.
- Constructor ensures the configured casino row exists with `CASINO_START_BALANCE = 100000`.
- `get_entry(user_id)` creates a zero-balance row when absent.
- `set_money`, `set_credits`, `add_money`, `add_credits`, `remove_entry` commit changes.
- `add_money` transfers the opposite amount to/from the runtime-bound `casino_user_id` for non-casino users. It clamps a player's resulting money/credits at zero; it does not reject negative input.
- `bind_casino_user(user_id)` switches the canonical casino account to the authenticated bot ID and migrates the configured casino row when the bot row does not already exist.
- `top_entries(n)` sorts by money; `get_all_entries()` returns all rows.
- Be careful with recursive `add_money` and nested commits when changing financial logic.

### `discord/modules/helpers.py`

- Loads YAML configuration and defines shared constants.
- Provides `make_embed(...)`, the standard Nextcord embed factory.
- Also defines `InsufficientFundsException` in this file; economy currently does not use it for normal balance checks.

### `discord/modules/base_betting_view.py`

- Shared Nextcord UI view for bet adjustment.
- Buttons: x10, +10, +1, /10, -10, -1, and close.
- `interaction_check` limits controls to the initiating user.
- `cap_bet` reads the view's `balance_index`; monetary views use tuple index 1 and slots uses credits at index 2.
- `bet_embed()` and `refresh_bet_message()` provide shared currency-aware rendering; `update_bet_message()` edits the interaction using the same embed.

### `discord/modules/base_game_cog.py`

- `BettingGameCog.prepare_bet_round()` is the shared wager orchestration used by blackjack, coinflip, dice, and slots.
- It validates the selected wager, sends the existing insufficient-funds response, deducts money or credits based on the betting view's `balance_index`, refreshes the betting message, and removes the previous game message.
- Each game cog remains responsible for its command, game generation, payout rules, and result message.

### `discord/modules/challenge.py`

- `ChallengeView` owns the Accept/Decline UI and restricts responses to the two challenged users.
- `ChallengeGameCog` owns challenge creation, acceptance-time balance checks, two-stake settlement, optional casino fees, and tie refunds.
- Coinflip and dice inherit `ChallengeGameCog`; ordinary betting remains in `BettingGameCog`.
- `ChallengeView` provides Accept/Decline controls for cash challenges.
- `open_challenge()` validates the opponent and challenger balance, creates the challenge thread, and charges both players only after acceptance.
- `settle_challenge()` pays the two-stake pot minus the optional `CHALLENGE_FEE_PERCENT`; `refund_challenge()` returns both stakes for ties.

### `discord/modules/card.py`

- `Card` represents suits clubs/diamonds/hearts/spades and values 2 through 14.
- Face values 11/12/13 map to jack/queen/king; 14 maps to ace.
- `image` maps to card asset names and uses `red_back.png` for down cards.

## Active cogs and commands

### `discord/cogs/blackjack.py`

- `/blackjack` creates a public thread and a bet-adjustment view.
- `BettingView` adds Start; `GameView` adds Hit and Stand.
- Uses the shared `BettingGameCog.prepare_bet_round()` flow before dealing.
- Deducts cash when the game starts, then pays blackjack/win/tie outcomes into cash.
- Generates a temporary composite PNG using Pillow, posts it, then removes it.
- Uses assets under `discord/modules/cards/` and expects `discord/modules/table.png`.
- `active_games` and `end_game_by_thread` exist for cleanup, but blackjack does not currently register the betting view in `active_games` at command creation in the visible implementation.

### `discord/cogs/slots.py`

- `/slots` creates a public thread with credit betting.
- Sends buy/sell instructions, then a credit bet view with Auto and the inherited bet controls.
- Uses the shared `BettingGameCog.prepare_bet_round()` flow; its view declares credits as the betting currency.
- Deducts credits per spin; matching three symbols pays `SLOTS_MULTS[symbol] * bet` credits.
- Uses Pillow assets `slot-face.png` and `slot-reel.png` under `discord/modules/` and creates a temporary GIF.
- `/buyc amount_to_buy` exchanges cash for credits at `TOKEN_PRICE`.
- `/sellc amount_to_sell` exchanges credits for cash.
- Buy/sell commands currently send success text even when the user lacks sufficient funds/credits, and inputs are not visibly validated for negative values.

### `discord/cogs/coinflip.py`

- `/coinflip` creates a public thread and cash bet view with Heads/Tails controls.
- Uses the shared `BettingGameCog.prepare_bet_round()` flow before flipping.
- Optional `/coinflip opponent bet` creates a challenge; the challenger is heads and the opponent is tails.
- Deducts cash when a side is selected; a win pays `bet * COINFLIP_MULT`.
- Posts a GIF from `discord/modules/cf-heads.gif` or `discord/modules/cf-tails.gif`.
- Supports Play Again through a game view.

### `discord/cogs/roller.py`

- `/diceroll` creates a public thread and should show a 1-6 guess selection.
- Uses the shared `BettingGameCog.prepare_bet_round()` flow before rolling.
- Optional `/diceroll opponent bet` creates a challenge; both players roll once and a tie refunds both stakes.
- Deducts cash only after a guess is selected; a correct guess pays `bet * DICE_MULT`.
- Supports Play Again.
- The duplicate `start_game`, duplicate inherited/explicit `close`, and duplicate `update_bet_message` definitions were removed. Roller now removes the inherited close component and uses one explicit `roller_close` X button.

### `discord/cogs/gambling_helpers.py`

- Prefix command `!add` grants `DEFAULT_BET * B_MULT`, with a static command cooldown despite config naming a bonus cooldown.
- Slash `/balance [user]` displays cash and credits and enforces the configured channel restriction.
- Prefix `!leaderboard` / `!top` displays five cash leaders.
- Hidden owner-only `!set` can set money/credits, but only truthy values are applied.

### `discord/cogs/leaderboard.py`

- `/casino_leaderboard` displays the top ten cash users, excluding `CASINO_USER_ID`.
- It is guild-scoped to `TEST_GUILD_ID`.

### `discord/cogs/help_command.py`

- `/help` documents the slash commands and attaches the aces image.
- Hidden owner-only `!kill` removes handlers and logs out.

### `discord/cogs/handlers.py`

- Prefix `on_command_error` handler for legacy/prefix commands.
- Handles command invocation, missing args, member lookup, permissions, insufficient funds, and cooldown errors.
- There is a known mismatch in historical logs: an unrecognized `wallet` command led to an attempted `help` lookup returning `None`; this path should be treated as legacy and checked before relying on it.

### `discord/cogs/legacy_gambling.py`

- Present in the repository but deliberately excluded from automatic loading by `bot.py`. Do not assume its commands are active.

## Thread cleanup

- `discord/modules/auto_thread_cleanup.py` polls one hard-coded `GAME_CHANNEL_ID` and imports timeout values from helpers.
- It skips archived threads and deletes cached, inactive threads older than the configured timeout.
- `setup_auto_thread_cleanup(client)` creates an asyncio task from `client.loop`.
- `/cleanup_threads` in `bot.py` is owner-only and invokes one cleanup pass.
- Cleanup only sees cached `channel.threads`; it does not fetch all remote threads.
- The module has a hard-coded channel ID separate from `CASINO_CHANNEL_ID`; keep these synchronized or move to one config source when fixing cleanup.

## Tests and verification

- Root `test_economy.py` is currently empty.
- `discord/test_economy.py` is a manual script: adds `discord/` to `sys.path`, removes row 0, adds money to `CASINO_USER_ID`, and prints the balance.
- There is no configured automated test suite visible in the repository.
- Basic syntax check from the root: `python -m compileall discord modules`.
- Manual runtime check: activate `.venv`, confirm the installed package is `nextcord`, ensure `config.yml` exists, then run `python discord/bot.py`.
- Never run a real bot with a credential copied into issue text or documentation.

## Known issues from project notes/logs

- Dice roll's duplicate UI custom IDs were fixed in `roller.py`.
- Wallet refreshes now update the persistent betting message after coinflip, dice, and slots results; continue tracing deductions and payouts through `Economy.add_money`/`add_credits` for transaction issues.
- Casino balance is bound during `bot.py`'s `on_ready` event to `client.user.id`; the owner balance command, money transfers, and leaderboard exclusion use the bound economy ID.
- Slots now has an explicit `slots_start` button in its betting view.
- Thread cleanup was previously reported as finding but not deleting threads; check cached-thread limitations, channel ID source, permissions, and timestamps.
- Nice-to-have: buying/selling slot credits in the slots thread is partly represented by global slash commands and an instruction embed.
- Future ideas in `Todo.txt`: coinflip/dice challenges, roulette, horse race betting.
- Coinflip and dice challenges are now implemented with optional opponent/bet arguments; the old solo paths remain available when arguments are omitted.

## Change guidance

- Treat `discord/` as the active application tree. Root `modules/auto_thread_cleanup.py` is a duplicate-looking leftover and is not imported by the active bot path.
- Preserve the tuple contract `(user_id, money, credits)` unless all callers are updated.
- When changing a game, test both the Discord UI component IDs and the economy transaction timing.
- Keep secrets out of `llm.txt`, logs, commits, and error reports. The local `config.yml` contains a bot token and should be handled as sensitive configuration.
- Prefer config-driven IDs and `__file__`-based paths over hard-coded IDs and cwd-dependent paths.
